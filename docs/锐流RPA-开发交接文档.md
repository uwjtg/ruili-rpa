# 锐流 RPA 客户端 · 开发交接文档

> 版本:V3(设计定稿) · 交接日期:2026-09-22 · 交接方:设计侧 → 编程开发侧
> 用途:本文档描述已完成的高保真 UI 原型的设计规格、交互清单、技术结构与开发边界,作为后续真实产品开发的输入。可直接把本文档与原型 HTML 一起交给编码会话使用。

---

## 1. 项目概述

- **目标产品**:一款对标影刀 RPA 的 PC 桌面自动化客户端。目标用户是电商运营、财务、HR 等业务人员:用拖拽指令的方式编排自动化流程,由计划任务/机器人按时间表执行,替代重复性网页与表格操作。
- **当前阶段**:UI/UX 已定稿(V3 高保真可交互原型),视觉与交互规格全部落在本原型与本文档中;业务逻辑、真实执行引擎、持久化均未实现(见 §7 开发边界)。
- **参照说明**:界面结构与操作路径参照影刀 RPA 客户端的成熟范式(降低用户迁移成本),视觉体系为自有设计;**未使用影刀的商标、logo 或任何品牌资产**。文中「锐流RPA」为占位品牌名,全部文案与数据为演示占位,交付前需替换为正式品牌信息。
- **设计定稿文件**:
  - `V3 锐流RPA-可交互原型.html` —— 高保真可交互原型(单文件、零依赖、双击即开),即"活的 UI 规格"
  - `V3 锐流RPA-无限画布.html` —— 设计交付画布(项目背景 / 设计系统 / 六屏设计稿缩略),适合整体浏览与设计评审
  - 历史版本 V1(蓝色方案)、V2(影刀对齐初版)在 `archive/` 目录,仅作追溯

## 2. 运行与查看方式

- 原型为纯静态单文件 HTML:双击打开,或放入任意静态服务器。无构建步骤、无外部依赖、无网络请求。
- 开发同事可直接阅读原型 HTML 源码:CSS 变量即设计 token,JS 顶部常量即示例数据模型,渲染函数即每个界面/组件的实现参照。

### 3.2 字体与排版

- 字体栈:`-apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`;日志/代码用 `Consolas, "Cascadia Code", monospace`
- 字阶:页面标题 18-19/600,区块标题 14-15/600,正文与控件 13,辅助 12,元信息 11,徽章 10-11
- 数字使用 `tabular-nums`;日志行:`时间戳(灰) + [级别](着色) + 消息`

### 3.3 形状与密度

- 圆角:按钮/输入 6px,卡片/面板 8px,弹窗 10px,胶囊 99px;步骤行 6px
- 信息密度:偏高(企业工具),控件高 26-30px,面板头 13px 600
- 阴影:仅悬停与浮层使用 `0 4px 14px rgba(31,35,41,.10)` 一档;其余用 1px 边框
- 图标:自绘 24 viewBox 线性 SVG,描边 1.7-1.9px、圆角端点、`currentColor`;**全站禁止 emoji 作图标**

### 3.4 关键组件规格

- **顶部标题栏(全局)**:红色圆形 logo(白字首字) + 产品名 + 版本胶囊 + 横向导航(选中项红色 3px 下划线) + 右侧:红色胶囊「邀请同事」、增值/帮助/通知图标(通知带红点)、头像、窗口控制(最小化/最大化/关闭)
- **开关**:34×19 胶囊,on 态红色(品牌开关,影刀式),off 态 `#D8DADD`
- **按钮**:主=红底白字;次=白底灰边;危险=红字浅红底;运行=绿底白字(编辑器内)
- **步骤行(编辑器核心)**:两行式,高约 52px —— 灰色序号(12px,右对齐) + 28×28 分类色圆角图标块 + 主行(13px/600 名称)与副行(11.5px 参数摘要);参数中的变量名渲染为 `蓝字 #2F80ED + 浅蓝底 #E8F0FE` 高亮
- **步骤区容器**:整体 2px `#7C5CFC` 圆角 8px 描边、底色 `#F8F7FC`,置于 `#F7F8FA` 画布上;循环/分支子步骤缩进 30px + 紫色竖向引导线;块尾为「分支结束 / 循环结束」标记行(紫色小方块旗图标 + 灰字,非交互)
- **AI 面板**:页签(当前紫色下划线);AI 气泡浅灰左对齐、用户气泡紫渐变右对齐;底部输入行 + 紫色发送按钮
- **任务卡**:36px 蓝色圆形时钟图标底 + 任务文案 + 元信息行 + 右侧下次执行/状态徽章/红色开关/记录按钮
- **空态**:居中图标容器 + 加粗标题 + 两行说明 + 主操作按钮(画布空态、搜索无结果等)

## 5. 编辑器交互清单(原型已实现,开发需对齐)

1. **添加指令**:指令库条目点击(插入到选中步骤之后,继承其层级)或拖拽(落点前/后插入,指示线反馈);画布底部「+ 点击搜索或选择常用指令」入口聚焦库搜索;空画布有引导空态与「添加第一条指令」按钮
2. **步骤选中与参数编辑**:点击选中(白底紫描边);右侧「参数」页签按指令的参数 schema 渲染表单(text/number/select),输入即时更新步骤摘要并标记"未保存";含「删除此步骤」
3. **变量**:变量表(名称/类型/初始值可编辑、可增删);变量名在所有步骤摘要中实时蓝色高亮
4. **步骤操作**(悬停显隐):断点(红色左缘圆点)、禁用/启用(整行半透明+摘要划线)、复制(深拷贝插至下一步)、删除;步骤可拖拽排序(拖拽手柄,落点前后指示线)
5. **运行模拟**:逐步骤点亮(紫描边+外圈光晕、自动滚动到可见),完成后序号变绿;日志流式追加(信息/成功/警告/错误四级配色+时间戳);结束 toast + 耗时统计;禁用步骤跳过并记日志
6. **调试**:与运行相同,但命中断点的步骤暂停,「运行」按钮变「继续」,可逐断点推进;「停止」随时中断(日志记错误)
7. **撤销/重做**:步骤与变量变更前自动快照(上限 60 步),按钮按栈空禁用
8. **保存**:清理未保存标记并 toast;顶部常显"已自动保存/有未保存的更改"
9. **标签页**:多流程并存、切换、关闭(最后一个不可关)、新建(自动命名);关闭运行中的流程会先中止运行
10. **AI 助手**:输入发送 → 用户紫色气泡 → 模拟回复(演示为固定话术池);开发时替换为真实 LLM 接口
11. **公告条**:右上 × 可关闭(会话级)

## 6. 原型技术结构(便于拆解移植)

- 单文件结构:`<style>`(全部设计 token 与组件样式,约 700 行) → 静态骨架(7 个 `.view` section) → `<script>` IIFE(数据 + 渲染 + 引擎,约 900 行)
- 渲染模式:数据驱动。核心状态:
  - `CMDS`:指令目录(分类 → 指令 → 参数字段 schema `{k,l,t,v,opts}` + 摘要函数 `s(params)` + 块尾标记 `end`)
  - `FLOWS`:`[{name, steps:[]}]`;step = `{uid, cmdId, name, ic, params, indent, disabled, bp}`;块尾标记 = `{uid, kind:'end', label, indent}`
  - `vars`:`[{name,type,value}]`(被 `fmtSummary()` 用于摘要高亮)
  - 其余:`APPS / TASKS / ROBOTS / RECORDS / MARKET / EDU` 演示数据
- 事件:全局委托(`data-run/data-edit/data-toast/data-win`) + 画布行内绑定(选中/操作/HTML5 DnD)
- 运行引擎:`runState` + `stepTick()` 定时器链(480ms/步,调试 900ms),断点用 `paused` + `_bpHit` 标记
- 已知简化(开发需重构):循环/分支在原型中以 `indent` 展平表达——真实实现建议改为**树形 AST**(节点含 `children`),渲染时递归生成缩进与结束标记,执行引擎直接遍历 AST

## 7. 开发边界:原型未覆盖、需真实实现的能力

| 模块 | 原型现状 | 真实产品需要 |
|---|---|---|
| 流程执行 | 前端模拟动画+假日志 | 指令执行引擎:网页自动化(建议 Playwright/CDP)、桌面自动化(鼠标键盘/窗口)、Excel/文件 IO、HTTP、OCR/LLM 调用;执行器与 UI 进程间通信(心跳/进度/日志流) |
| 元素拾取 | 元素库为空列表+占位按钮 | 全局拾取服务(注入脚本/坐标捕获)、选择器生成与校验、元素库持久化 |
| 智能录制/数据抓取 | 占位按钮 | 操作录制器(点击/输入/滚动事件→指令序列)、相似元素抓取算法 |
| AI 助手 | 固定话术池 | LLM 接入(指令生成/报错解释/方案推荐),上下文注入当前流程 AST |
| 计划任务/触发器 | 本地状态开关 | 调度器(cron/间隔/高级触发),错过补跑、并发与队列 |
| 机器人 | 3 张演示卡 | 本机执行器注册、云端节点管理、心跳、远程下发、并发锁 |
| 持久化 | 内存态,刷新即失 | 应用/流程/变量/日志的本地存储(SQLite/JSON)+ 云同步与团队协作 |
| 账号/版本 | 静态文本 | 登录、社区版/企业版权益、邀请同事流程 |
| 日志 | 前端数组 | 执行日志落盘、检索导出、错误堆栈关联步骤 |
| 窗口控制/更新 | 演示占位 | 打包安装、自动更新、托盘、开机自启 |

## 8. 建议技术栈与工程结构(建议,团队可自行取舍)

- **壳**:Electron(生态成熟、Node 侧可直接挂自动化库)或 Tauri(更轻,自动化库走 sidecar 进程)
- **前端**:Vite + React/Vue;原型 CSS token 直接迁移为 CSS 变量/Design Token,组件按 §3.4 拆分
- **流程模型**:JSON AST(节点:id、cmdId、params、children);编辑器状态用不可变快照支持撤销/重做;执行前做拓扑校验(未闭合块、空分支)
- **执行引擎**:Node 侧 Playwright(网页)+ 可选 Python sidecar(桌面自动化/OCR);日志经 IPC 流式推送 UI
- **存储**:SQLite(应用/流程/任务/日志);变量与凭据加密存储
- **建议目录**:
  ```
  app/
    src/renderer/        # UI(按原型 7 视图拆组件)
    src/main/            # 主进程:窗口、调度、IPC
    src/engine/          # 指令注册表、执行器、录制、拾取
    src/shared/          # 指令 schema(与 UI 共用)、AST 类型
  ```

## 9. 质量基线(当前原型已通过的自检,可作为 UI 验收口径)

- 逐界面无头渲染 + 图像识别质检 11 项全部通过(首页/编辑器四区/应用/触发器/机器人/市场/教程/新建弹窗/运行结束态/步骤选中态/窄屏 700px),运行时零 JS 错误(全局错误探针验证)
- 交互验收点:添加指令两条路径、参数即时生效、变量高亮联动、断点暂停/继续、禁用跳过、拖拽排序、撤销重做、标签页互斥与关闭中止运行
- 响应式:1023px 抽屉化、767px 导航折叠,700px 宽无横向溢出
- 无障碍基线:图标按钮均带 `aria-label`、开关带 `role="switch"`、弹窗 `role="dialog"`、`:focus-visible` 可见
