## 1. 本阶段目标与完成情况

计划书 §6.3 提到「AI 面板同时做报错解释」。此前运行失败只能看原始日志，用户要自己判断哪步炸了。本次加一键解释：

- **纯函数**（`src/engine/llm/explainError.ts`）：
  - `buildExplainPrompt(flowName, entries, error?)`：把最近 80 条日志拼成中文解释 prompt（超 80 条截断，防超长）；
  - `explainRunError(client, flowName, entries, error?)`：用当前激活 Provider 普通 chat（无 function-calling，temperature 0.3）返回解释文本。
- **主进程 IPC**（`src/main/index.ts`）：`llm:explain-error`（入参 runId）——从 DB 读该 run 的日志明细 + 历史项里的 flowName/status，调 `explainRunError`，返回 `{ok, explanation?}`。
- **UI**（`RobotsView.tsx`）：错误状态（error/failed）运行项展开后，日志区下方出现「✦ AI 解释此错误」按钮；点击后 loading→紫色气泡显示解释；展开其他项自动清空上一次结果。
- preload/env.d.ts 同步 `llm.explainError(runId)`。

不自动调 LLM（费钱/隐私），用户点按钮才调；用当前激活配置（设置里配的便宜模型即可）。未改 FlowDoc/RunWireEvent。

## 5. 遗留问题

1. `RunResult.error` 原始字符串没落 DB（logs 表只存 level/message/ts/status），解释时只能从 error 级别日志反推；后续可在 logs 表加 error 列。
2. 解释文本是纯文本，没做 markdown 渲染；长建议会换行显示。
3. 设计器编辑器的日志面板没接这个按钮（只在 RobotsView 历史项里）；编辑器里现场失败可后续加。

## 6. 对下一阶段的输入要求
