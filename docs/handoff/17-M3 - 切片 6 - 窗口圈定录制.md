## 1. 切片目标

关闭切片 3/4/5 §6 一直挂账的**录制噪声**问题：此前录制是全局钩子 + 仅排除自身 app_pid，
用户点到任何其它窗口的操作都会被录下。本切片让用户**先圈定目标窗口**，录制只保留该窗口
所属进程 PID 的事件：

1. **录制范围按 PID 圈定**：`record:start` 新增可选 `target_pid`；录制聚合时，点击/滚动按
   事件坐标处窗口 PID、按键按事件时前台 PID，只保留等于 `target_pid` 的事件（仍同时排除
   自身 app_pid）；
2. **窗口句柄 → PID**：新增 sidecar `/desktop/window_pid {hwnd}`（GetWindowThreadProcessId）；
3. **UI 一步圈定**：编辑器工具条加「圈定窗口」按钮 → 复用拾取框点选目标窗口 → 主进程取回
   顶层窗口 PID 并显示；之后「录制」只录该窗口。

**不做的**（顺延切片 7）：坐标兜底按窗口重定位加固、聚合阈值真实样本校准、录制流程参数化。

## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 圈定单位 | 进程 PID（非窗口句柄） | 录制钩子本就捕获前台 PID；点击/滚动按坐标处窗口 PID，与既有过滤同构 |
| 与排除自身的关系 | target_pid 与 app_pid 叠加：非目标丢弃 + 自身丢弃 | 圈定后仍不会录到编辑器 |
| 如何取 PID | 拾取框点选目标窗口元素 → 取其 windowHandle → GetWindowThreadProcessId | 复用既有 /pick/start，无需新交互 |
| 未圈定行为 | target_pid=0 → 不过滤，等同切片 3-5 行为 | 向后兼容，不破坏既有流程 |
| 圈定时机 | 录制前点一次；录制中显示「圈定:标题」 | POC 足够；跨窗口切换不动态重圈（挂账） |

## 5. 遗留与风险

1. **跨窗口切换不动态重圈**：录制中用户切到另一个应用，其事件会被丢弃（正是期望），但切回
   圈定窗口内的子进程/多窗口仍按 PID 归并；若目标应用多进程（如 Chromium 多 tab 不同进程），
   只会录到第一个圈定的主进程。
2. **坐标兜底点偏未根治**：仍挂账（切片 7 候选：回放前按窗口标题重定位+偏移修正）。
3. **聚合阈值未校准**（350/800/400ms）。
4. **圈定后无「取消圈定」按钮**：当前点新「圈定窗口」即覆盖；清空圈定需重开录制页。
5. **Tcl leaked 告警（既有）**：overlay 线程退出已知行为。

## 6. 下一步建议（优先级排序）

1. **坐标兜底加固**：回放 coords 点击前按 windowTitle 重定位窗口，把旧 boundingBox 换算到新偏移。
2. **聚合阈值校准 + 可配置**：录真实操作人工核对后调阈值，做成可配置。
3. **录制流程参数化**：录制出的字面文本/坐标暴露为可改变量。
4. **圈定体验完善**：录制中显示当前圈定窗口、支持「取消圈定」；多进程目标应用按顶层窗口树圈定。
