## 1. 本阶段目标与完成情况

M4-1/2 向导已能识别列表，但示例项选择器仍要用户手填或从 DevTools 复制——这是真实使用的最大门槛。本切片把"点选"做成一等公民：

1. 页面脚本 `pick-script.ts`：
   - `CSS_PATH_FN`：从元素向上生成稳定 CSS 路径（祖先 id 截断、tag.class、`:nth-of-type` 消歧、跳过尾部 hash 类名）；
   - `PICK_START_FN`：注入紫色高亮框（z-index 2147483647、pointer-events:none）、mousemove 跟踪 `elementFromPoint`、mousedown capture 阶段 preventDefault+stopPropagation、Esc 取消；
   - `PICK_READ_FN`：主进程等待后读结果。
2. `WebSession.startPagePick(timeoutMs)`：三段字符串拼一起 `new Function` 包成函数对象注入（避开 CSP）→ `page.waitForFunction(__ruiliPickDone)` → 读 `__ruiliPickResult`。
3. 主进程 `web-pick.ts` + IPC `web-pick:start` + preload `ruili.webPick.start` + env.d.ts 类型。
4. 向导示例选择器输入框旁加「在页面中点选」按钮，点选成功自动回填选择器并提示已选文本。

**不做**：完整浏览器录制器（点击/输入/滚动录制成指令序列——那是后续大项）；拾取字段级元素（M4 先只点示例项，字段仍走聚类自动识别）；iframe 内拾取。

## 5. 遗留问题

1. **真浏览器端到端未冒烟**：CSS 路径生成只在 linkedom 测过，真实页面对动态 class/Shadow DOM/svg 路径未验证；高亮框在 iframe 内不工作。
2. CSS 路径取第一个 class token（`class="a b c"` 只取 a），多 class 场景可能选错。
3. `nth-of-type` 基于兄弟 tag 计数，异步渲染前后 DOM 变化可能让路径失配。
4. 拾取后不自动触发「识别相似项」，用户还需点一次按钮——可做成选中即自动识别。
5. 浏览器未启动时按钮直接报错，未引导用户先开浏览器。
