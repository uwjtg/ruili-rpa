# 阶段 3 交接文档（真实链路：网页 CDP + Excel 读写 + Python sidecar）

> 日期：2026-09-24 · 上游：《接力开发模式说明》《计划书 V1.1》《开发交接文档 V3》《handoff/02》
> 范围：T4（网页 CDP）+ T5（Excel 读写）+ T6（Python sidecar）

## 1. 本阶段目标与完成情况

**目标**：把阶段 2 的 mock 指令替换为真实外部链路——Playwright CDP 驱动真实浏览器、exceljs 读写 .xlsx、Python sidecar HTTP 桥；三个 POC 脚本实跑通过。

**完成情况**：全部完成，§2 验收三项（`poc:web` / Excel round-trip / `poc:sidecar`）均实跑通过。

- **网页 CDP**（`src/engine/web/`）：`RealWebSession` 用 `playwright-core` 的 `launchPersistentContext` 启动**独立 userDataDir profile**（计划书 B4：独立 profile，目标站需重新登录）；channel 按 `msedge → chrome → 默认` 回退；无头模式。新增 6 条指令：`webOpenBrowser / webOpenUrl / webClick / webInput / webExtractText / webCloseBrowser`。
- **Excel 读写**（`src/engine/excel/`）：`RealExcelSession` 基于 exceljs（纯 JS，**不启动 Office/WPS 进程**）；新增 5 条指令：`excelCreate / excelOpen / excelWriteCell / excelReadCell / excelSave`。
- **Python sidecar**（`sidecar/`）：`server.py` 仅用标准库起 HTTP 服务（127.0.0.1），握手行 `SIDECAR_READY port=N`；端点 `GET /health`、`POST /ocr`、`POST /find_image`；RapidOCR/OpenCV 为可选增强，缺失时返回结构化 501 优雅降级。Node 侧 `SidecarClient` 负责选空闲端口、spawn 子进程、握手、HTTP 调用。新增 3 条指令：`sidecarStart / sidecarOcr / sidecarStop`。
- **可测性设计**：三条链路都做了「会话抽象」（`WebSession` / `ExcelSession` / `SidecarLike`），指令 runner 依赖抽象而非具体实现；单测全部注入 stub，不在 CI 真起浏览器/Office。

**未完成 / 留后续**：
- 选择器回退链（id→name→aria→css→xpath→文本）：本阶段只用 Playwright 原生 CSS/text 选择器，回退链是 M3（拾取/录制）的核心设计。
- OCR 真实识别：RapidOCR 未 pip 安装，`/ocr` 当前走 501 降级（桥已通）；OpenCV 在本机已可用，`/find_image` 已能跑真实模板匹配。
- 资源生命周期管理：浏览器/Excel/sidecar 是模块级单例，尚未与「一次流程运行」绑定（流程结束自动关浏览器/存盘/杀 sidecar）——阶段 4 接主进程时补。
- COM 高保真 Excel 轨（驱动真实 Office/WPS）未做，主轨 exceljs 已满足 POC。

## 5. 遗留问题（含影响与建议）

1. **网页 POC 只用离线 data: URL**，未在真实站点验证选择器稳定性——这是 M3 的核心（回退链），本阶段只证明 CDP 启动/导航/输入/点击/提取通路。建议阶段 6 出口演示用真实搜索站验证一次。
2. **RapidOCR 未安装**：`/ocr` 返回 501。本机 OpenCV 已装、`/find_image` 可用。建议阶段 5 指令扩充时 `pip install rapidocr-onnxruntime`（含模型约百 MB），启用真实 OCR；当前桥已通，装包即可用、无需改代码。
3. **浏览器实际落到 Chrome**：本机 Edge 不在标准安装路径，channel 回退链选中了 Chrome。两引擎都走 Chromium/CDP，行为一致；阶段 6 出口演示如需 Edge 再指定 channel。
4. **资源未与运行生命周期绑定**：浏览器/Excel/sidecar 为模块级单例，流程跑完不会自动关闭浏览器或保存 Excel。影响：POC 脚本手动 close()；接 UI 后可能残留浏览器进程。建议阶段 4 在主进程维护「一次运行的资源句柄」，flowEnd 时统一清理。
5. **sidecar 运行中崩溃无重连**：当前仅握手阶段错误处理；运行中 Python 退出会导致后续 HTTP 调用失败。阶段 4 加健康探测定时与自动重启。
6. **Git 基线仍缺**（沿用阶段 1/2 遗留）：本机 Git 异常未修复，代码仍未提交版本库。不阻塞开发。

## 6. 对下一阶段（阶段 4 · 贯通与 AI）的输入要求

- **引擎契约不变**：新指令照旧 `register()` 进 `CommandRegistry`；runner 通过 `ctx` 交互，不要直接持 Interpreter。
- **阶段 4 落点提示**：
  - 主进程（`src/main/`）新建一个 `CommandRegistry` 实例，同时 `registerDemoCommands` + `registerWebCommands` + `registerExcelCommands` + `registerSidecarCommands` 注册进去，这样一份流程里可混用演示指令与真实链路指令。

  - sidecar 的 `SidecarClient` 应由**主进程持有**（渲染端不 spawn Python）；浏览器/Excel 单例同理。
- **会话抽象已可注入**：`setWebSessionForTesting` / `setExcelSessionForTesting` 仅测试用；生产用默认单例。
- **公共文件**：阶段 4 若接 LLM，新增 openai 兼容依赖（建议 `openai` SDK 或直接 fetch），务必在交接文档声明 license 与 baseURL/apiKey 配置位置（计划书决策⑤，apiKey 用 safeStorage/DPAPI 加密）。
