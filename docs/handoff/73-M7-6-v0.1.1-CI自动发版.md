## 1. 本阶段目标与完成情况

承接 72 号推荐：做 0.1.1 发版演练，验证"推 tag → CI 出包 → Release 发布"全自动链路。

**完成内容：**
- `npm version patch`：package.json 0.1.0 → 0.1.1，自动打 tag `v0.1.1`，commit `6372f6a`。
- `git push origin main && git push origin v0.1.1` 触发 Release workflow。
- Release workflow 全绿：
  - Setup Node 22 / Python 3.12 → pip 装 uiautomation/comtypes → `npm ci` → `npm run build:sidecar`（裁 Python + RapidOCR，成功）→ `npm run build`（electron-vite，成功）→ `npx electron-builder --win nsis --publish always`（成功）→ `node scripts/ci-unpublish-release.mjs`（成功）。
  - 总耗时约 6 分钟（03:05:06 触发 → 03:11:05 完成）。
- v0.1.1 Release 已正式发布：https://github.com/uwjtg/ruili-rpa/releases/tag/v0.1.1
  - 资产：`ruili-rpa-0.1.1-setup.exe` (258.0 MB) + `.blockmap` + `latest.yml`
  - latest.yml 内容正确：version 0.1.1，size 270563105，sha512 齐全。

**过程中修掉两个 CI bug：**

1. **ci.yml 漏装 pytest**：CI 上 `npm run test:sidecar` 报 `No module named pytest`（只 pip 装了 uiautomation/comtypes）。修：`pip install uiautomation comtypes pytest`。
2. **electron-builder 并发上传建了两个 draft release**：日志显示 "creating GitHub release" 出现两次，blockmap 传到一个 draft（id …849），.exe+latest.yml 传到另一个 draft（id …848）。旧 un-draft 脚本只翻了带 blockmap 的那个，导致 .exe+latest.yml 留在 draft 里、published release 残缺。修：
   - 手工把 blockmap 搬到 …848、翻 …848 为 published、删 …849（v0.1.0 同样问题也手工修了）；
   - un-draft 脚本升级：选 assets 最多的同 tag release 发布，其余同 tag draft 全删。

## 5. 遗留问题

1. **装机版真升级未端到端验证**：当前装机版（`%LOCALAPPDATA%\Programs\ruili-rpa\锐流RPA.exe`，v0.1.0）的 `resources/app-update.yml` 里 `owner: ruili-rpa`（70 号打的旧包，当时 owner 还是占位），不是 `uwjtg`。所以装机版点"检查更新"会去查 `github.com/ruili-rpa/ruili-rpa`（不存在），查不到 v0.1.1。**这是 70→71 的历史遗留**：71 号改了 owner 重打了 v0.1.0 Release，但装机版还是更早的包。
2. **本机到 GitHub release CDN（objects.githubusercontent.com）不通**：无法下载 258MB 的 v0.1.1 安装包覆盖装机版。需在网络可达 GitHub 的环境下下载安装包重装。
3. **修复路径**：下次用户在网络好时，从 https://github.com/uwjtg/ruili-rpa/releases/tag/v0.1.1 下载 setup.exe 双击安装（覆盖旧版），新包的 app-update.yml 会是 owner: uwjtg，之后"检查更新"链路即通。
4. 新 push 的 CI run（修 pytest 后）在跑，需确认转绿。
5. 代码签名证书仍未配。
