> 日期：2026-09-24 · 上游：《接力开发模式说明》《计划书 V1.1》《开发交接文档 V3》《handoff/01》
> 范围：T2（AST 解释器）+ T3（指令注册表 + 演示指令）+ 断点/暂停-继续

## 1. 本阶段目标与完成情况

**目标**：在 `src/engine/` 落地可运行的薄编排引擎——树形 AST 遍历、变量作用域、指令插件注册表、8 条演示指令、断点暂停/继续/停止；用自动化测试证明主路径。

**完成情况**：全部完成，验收三项（§2）均达成。

- **AST 解释器**（`src/engine/core/interpreter.ts`）：深度优先遍历 `FlowDoc.steps` 树；作用域栈（全局 + 块指令绑定的局部作用域）；变量读写沿栈查找；`${var}` / `${var.prop}` 插值；禁用步骤跳过；取消令牌 `stop()`；断点 `breakpoint` 命中断在执行前暂停、`resume()` 继续。
- **指令注册表**（`src/engine/commands/registry.ts`）：`CommandRegistry`（register/get/has/list），重复 id 抛错；`RegisteredCommand = CmdMeta + runner`。
- **8 条演示指令**（`src/engine/commands/demo.ts`）：`logMessage` / `delay` / `setVar` / `httpGet`(mock) / `jsonParse` / `randomInt` / `loopList`(块) / `ifVar`(块)。全部不依赖真实外部进程（浏览器/网络/Excel 均 mock），真实链路留阶段 3。
- **shared 契约**（`src/shared/`）：`ast.ts`（FlowDoc/StepNode/FlowVar/RunResult）、`cmd-schema.ts`（CmdMeta/ParamField）、`events.ts`（RunEvents/LogLevel）。
- **5 步演示流程**（`src/engine/core/demo-flow.ts` + `scripts/demo-run.ts`）：开场日志 → mock HTTP GET → 循环遍历（子步骤插值输出商品）→ 设置汇总 → 输出汇总。断点暂停/继续经 `npm run demo:engine` 可视化验证。

**未完成 / 留后续**：
- 流程 AST 静态校验（块闭合、空分支、变量未定义警告、循环深度上限）——本阶段未做，解释器对畸形 AST 直接抛错或静默；建议阶段 4 编辑器保存时补校验层。
- 单步执行、变量监视、步骤超时、指令重试——阶段 4+。
- 引擎尚未接 IPC / 主进程 / 渲染端（EditorView 仍是占位）；事件回调目前是进程内直调，阶段 4 接 IPC 时补 wire 格式。

## 5. 遗留问题（含影响与建议）

1. **流程 AST 未做静态校验**：畸形树（未闭合块、引用未定义变量、循环过深）目前靠运行时抛错暴露。影响：编辑器阶段若让用户随便连线，可能运行到中途才报错。建议：阶段 4（编辑器真实化）在保存/运行前加 `validateFlow(flow): FlowIssue[]` 校验函数，落在 `src/engine/core/validate.ts`。
2. **`httpGet` 是 mock，未发真实网络**：阶段 3 接 Playwright/真实 HTTP 时，本指令的 runner 需替换为真实 fetch（保留 resultVar 契约），或新增 `webOpen`/`webClick` 等指令。
3. **变量插值仅支持 `${var}` / `${var.prop}` 单层点路径**：不支持 `${arr[0].x}` 下标、表达式、运算。阶段 4 接 AI 生成流程时若需要更复杂表达式，再扩展解析器。
4. **断点只支持"步前暂停"，不支持单步（step-over/step-into）**：验收要求"断点暂停/继续可用"已满足；单步调试留阶段 4。
5. **引擎尚未接主进程/IPC**：`Interpreter` 目前只能在 Node 侧直接 `run()`；EditorView 仍是占位。阶段 4 接 IPC 时，主进程持有 Interpreter 实例，渲染端通过 IPC 调 run/resume/stop 并订阅 RunEvents。
6. **Git 基线仍缺**（沿用阶段 1 遗留）：本机 Git for Windows 异常未修复，本阶段代码同样未提交版本库。不阻塞开发；建议用户修复 Git 后一次性 `git init && git add -A && git commit`。

## 6. 对下一阶段（阶段 3 · 真实链路）的输入要求

- **引擎契约已固定，请勿破坏**：
  - `FlowDoc/StepNode` 见 `src/shared/ast.ts`；块嵌套用 `children`/`else`，不要回到原型的 indent 展平表达。
  - 新指令一律 `register()` 进 `CommandRegistry`：UI 元数据（id/name/group/icon/params/summary/hasEnd）填 `RegisteredCommand`，执行逻辑写 `runner(ctx, params, step)`。
  - `ctx` 提供 `getVar/setVar/log/execChildren/isCancelled/interpolate`——新指令通过这些与流程交互，**不要**直接持有 Interpreter 实例。
  - 块指令（有 children 的）在 runner 内通过 `await ctx.execChildren(step.children, { itemVar: item })` 递归执行；局部变量经 bindings 注入，执行完自动出栈。
- **阶段 3 落点**：
  - `src/engine/web/`：Playwright CDP 附加真实 Edge/Chrome；新增 `webOpenUrl`/`webClick`/`webInput`/`webExtractText` 等指令，注册进同一 Registry。
  - `src/engine/excel/`：exceljs 读写；新增 `excelOpen`/`excelWriteCell`/`excelReadRow` 等。
  - `sidecar/`：Python 侧骨架 + HTTP/stdio 桥；OCR/找图 POC。
  - 新指令 runner 真实调用外部进程后，**用 mock/stub 写单测**（不要在 CI 里真起浏览器/Excel）；端到端 POC 脚本放 `scripts/`。
- **事件类型**：`RunEvents`（`src/shared/events.ts`）已定义全部钩子；阶段 3 若需新增事件字段（如变量快照、选择器命中详情），在此文件加可选字段，保持向后兼容。
- **公共文件**：阶段 3 需新增依赖（playwright / exceljs / better-sqlite3 等），务必在交接文档中逐条声明 `package.json` diff 与许可证。
