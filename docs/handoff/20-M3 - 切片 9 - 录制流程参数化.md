## 1. 切片目标

关闭切片 8 §6 优先级 #1：**录制流程参数化**。

此前录制出的 `typeText` 步骤把输入文本硬编码在 `params.text` 里；改输入内容要逐步骤编辑。
运行时引擎本就支持 `${var}` 插值（`ctx.interpolate`），流程也有 `FlowDoc.vars`。本切片把录制
落地的硬编码输入文本**自动抽成流程变量**：

1. 新共享纯函数 `parameterizeRecording(instructions, existingVars?)`：把 `typeText` 的字面文本
   生成 `input1/input2…` 流程变量（默认值=录到的文本），步骤 `params.text` 替换为 `${inputN}`；
2. 渲染层追加录制步骤时合并新变量到 `flow.vars`，并提示用户去「变量」面板修改；
3. 只参数化 `typeText.text`；已含 `${}` 的文本与 pickElement/scroll/pressKey 不动，向后兼容。

回放行为不变：变量默认值就是录到的文本，`ctx.interpolate` 仍输回原文。

**不做的**（顺延切片 10）：坐标/滚动量参数化、变量默认值编辑 UI 细化、阈值设置面板与持久化。

## 2. 完成项（代码落盘清单）

### 2.1 新共享模块 `src/shared/record-params.ts`
- `parameterizeRecording(instructions, existingVars=[])` → `{steps, vars}`：
  - 遍历指令；仅当 `cmdId==='typeText'` 且 `params.text` 为非空字符串、不含 `${` 时抽变量；
  - 变量名 `inputN`，避开 `existingVars` 已有名字；
  - 返回的 `steps[].params.text` 已替换为 `${inputN}`；
  - 其余指令原样透传。

### 2.2 渲染层 `EditorView.tsx`
- import `parameterizeRecording`；
- `appendRecordedSteps` 先调用它（传入 `activeTab.flow.vars`），再把参数化后的步骤序列化入列，
  并把 `newVars` 合并进 `flow.vars`；新增变量时推送一条 sys 日志提示变量名。

### 2.3 测试 `src/shared/record-params.test.ts`（+4，共 106）
- typeText 多段文本各自抽为 input1/input2，步骤变 `${var}`；
- 其它指令与已含 `${}` 的文本不动；
- 避开流程已有变量名（input1 已存在 → 新变量 input2）；
- 空文本不抽变量。

## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 参数化范围 | 仅 typeText.text | 文本是录制中最常变的输入；坐标/选择器是定位特征，参数化语义复杂 |
| 变量命名 | input1/input2… 自动编号，避开重名 | 无需用户命名，POC 最小可用 |
| 默认值 | 录到的文本 | 回放不改变行为（变量未改=原文），向后兼容 |
| 已含 `${}` 的文本 | 不动 | 用户手填的引用不被二次包装 |
| 在哪一层做 | 渲染层追加步骤时（纯函数） | 不污染 sidecar 协议；纯函数可单测 |
| pressKey/scroll | 不抽 | 按键/滚动量是固定操作，不是可输入内容 |

## 5. 遗留与风险

1. **只参数化文本**：点击坐标兜底、滚动量、按键未参数化。
2. **变量无类型/描述 UI**：VarPanel 已有变量面板，但未为本切片新变量加注释/分组。
3. **录制前已有同名变量**：靠 `inputN` 递增避让，极端下可能与用户自定义语义名冲突（不报错）。
4. **阈值设置面板 + 持久化**、**坐标兜底点击前置窗口**、**圈定体验完善**仍挂账。

---

## 6. 下一步建议（优先级排序）

1. **变量/参数面板完善**：录制抽变量时带默认值与说明；支持在运行前弹窗填变量（run dialog）。
2. **坐标/滚动量参数化**：把坐标兜底位置与滚动 delta 也暴露为可改参数。
3. **阈值设置面板 + 持久化**：编辑器调聚合阈值并落盘。
4. **坐标兜底运行层加固**：点击前 SetForegroundWindow 置前。
