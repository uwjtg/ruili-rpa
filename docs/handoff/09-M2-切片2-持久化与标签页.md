> 范围：M2（编辑器真实化）第二个可交付切片——接 better-sqlite3 本地持久化，把"内存态单流程编辑器"升级为"多标签页 + 可保存/加载/删除 + 应用视图真实列表"。拖拽排序、单步调试、AI 面板、运行日志落盘留后续切片。

## 1. 本切片目标与完成情况

**目标**：让流程从"刷新即丢"变成"可落盘、可重开、可在应用页管理"，并把编辑器从单流程升级为多标签页。

**完成情况**：任务清单全部达成。

- **better-sqlite3 安装与建库**（计划书 §4.1 选型，MIT）：装 `better-sqlite3@^13.0.3`（+ `@types/better-sqlite3@^9.6.0` dev）。v13 走 Node-API（prebuilds/*.node），Node 与 Electron 共用同一二进制，**无需 @electron/rebuild**。主进程 `whenReady` 打开 `userData/ruili.db`，WAL 模式 + 外键开关；建三张表 `apps / flows / logs`（logs 本次建表，运行落盘后续切片填）。
- **流程 CRUD IPC**：`flow:save / flow:list / flow:load / flow:delete` 四条 handle；preload 暴露 `ruili.flow.*`；可序列化形状抽到 `src/shared/flow-protocol.ts`（renderer 不依赖 main 模块）。save 事务性 upsert flows + 镜像 apps（1:1），delete 级联清 logs/flows/apps，list 按最近编辑倒序（同毫秒用 rowid 兜底）。
- **编辑器多标签页**：EditorView 重写为 `EditorTab[]` 模型——每个标签独立持有 flow / flowId / dirty / savedAt / selectedId / runningStepId / doneIds / undo-redo 双栈。支持多 FlowDoc 并存、点击切换、✕ 关闭、"+ 新建"；**最后一个标签不可关**；**关闭运行中标签先 `run:stop()`**；关闭有未保存更改的标签弹确认。运行事件按 `runningTabRef` 路由到对应标签，切走不影响运行高亮。
- **保存按钮 + 状态标记**：工具栏红色「保存」主按钮；标签标题脏标记 `●`（红）；工具栏右侧三态——`● 未保存的更改`（红）/ `✓ 已保存 HH:MM`（绿）/ `尚未保存`（灰）。保存成功后标签绑定 flowId、dirty 清零。
- **应用视图真实化**：AppsView 从 PlaceholderView 占位重写为卡片网格——`flow:list` 拉真实 SQLite 列表，卡片显示名称/步骤数/最近编辑时间，「编辑」跳 `/editor?flowId=xxx`（EditorView 读后端子加载并激活该标签），「删除」走 `flow:delete` 并刷新，「+ 新建应用」跳 `/editor`；空态/加载态/错误态齐全。

## 5. 遗留问题

1. **手动保存，未做自动保存**：§5 第 8 条原文"已自动保存"。当前实现为手动点「保存」+ 脏标记；自动保存（debounce N 秒写库）未做。影响：用户编辑后不手动点保存就关掉会丢（已有 confirm 提示）。建议切片 3 加 3s debounce 自动保存，文案切回"已自动保存"。
2. **logs 表建了但未写**：本切片只建表，运行日志仍只走 IPC 到 UI 面板，未落盘。建议切片 3 在 `flow-end` 时把本次运行的 lines 批量 INSERT 进 logs（带 flow_id/run_id/status/duration_ms），为机器人执行记录打地基。
3. **应用卡片无「运行」入口**：§4 应用视图关键交互有"运行"进编辑器并自动跑。本切片只做「编辑」；卡片「运行」按钮留切片 3（或 M4）。
4. **关闭运行中标签的 stop 是 fire-and-forget**：`run:stop()` 后立即关标签，flow-end 事件回来时 `runningTabRef.current` 已清空，不会报错；但 UI 上 running 标志要靠 flow-end 才清。若用户极快连续关多个标签，时序窗口已测（单 RunManager）。影响很小，记录在案。
5. **未做重命名流程名**：编辑器没有"另存为/改名"入口；流程名改了不会自动落盘（改 flow.name 后需再点保存）。建议切片 3 加标签双击改名 + 重命名按钮。
6. **Git 基线仍缺**（沿用 M0/M1）：本机 Git for Windows 异常未修复，本切片代码未提交。不阻塞开发。

## 6. 对下一切片（M2 切片 3：拖拽 + 单步调试 + 日志落盘）的输入要求

- **持久化已就绪**：编辑器任何时刻调 `ruili.flow.save(flow, flowId?)` 即可落盘；多 tab 下每个 tab 自带 flowId 与 dirty。切片 3 做自动保存时，在 `commit()` 末尾挂一个 3s debounce 调 save 即可，不用动存储层。
- **flow-protocol 形状冻结**：`FlowSummary/SaveReply/LoadReply/ListReply/DeleteReply` 已过 IPC，后续切片不要改；要扩展字段就加可选。
- **不要改** `RunWireEvent`（切片 1 已强调）；多 tab 下运行事件路由靠 `runningTabRef`，切片 3 加 step-over/into 时沿用这个 ref。
- **AppsView 可复用**：切片 3 加卡片「运行」时，直接 `navigate('/editor?flowId=x&autorun=1')`，EditorView 读 searchParams 里的 `autorun` 自动调 `run()`。
- **logs 表 DDL 已就绪**：`logs(id PK AUTOINCREMENT, flow_id, run_id, level, message, status, duration_ms, ts)`；切片 3 在主进程 `run:event` 的 `flow-end` 分支批量落盘即可，renderer 不用改。
- **better-sqlite3 NAPI**：后续若加新表（元素库/任务/机器人执行记录），直接在 `db.ts` 的 `migrate()` 里 `CREATE TABLE IF NOT EXISTS`，幂等。
