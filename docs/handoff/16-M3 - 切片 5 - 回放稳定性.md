## 1. 切片目标

关闭切片 2 §7 与切片 3/4 §6 挂账的**回放稳定性**风险：此前 `pickElement` 回放只跑一次
回退链，目标应用尚在加载 / 窗口句柄刚失效 / 元素未就绪时一次落空就直接报错，且坐标兜底
会拿过期 boundingBox 点错位置。本切片给回放加：

1. **定位失败自动重试**：`click_element` 未命中时等一小段再试，默认重试 2 次（共 3 次尝试）；
2. **每次重试重跑整条定位链**：窗口句柄失效时 `locate_element` 本就会按 `windowTitle`
   重取窗口根——重试天然实现「重取窗口句柄」，无需额外状态；
3. **失败原因透传**：重试耗尽后抛错消息把逐级 trace 拼进去（`窗口句柄 x 失效 | 全部策略落空`），
   主进程 404 回给运行日志，便于排查。

**不做的**（顺延切片 6）：窗口句柄圈定录制范围（需 UX 拍板如何指定目标窗口）、聚合阈值
按真实样本校准、录制流程参数化。

## 2. 完成项（代码落盘清单）

### 2.1 sidecar `desktop_pick.py`
- `DesktopPicker.click_element(target, retries=2, retry_delay=0.3)`：
  - 循环 `retries+1` 次，每次都调 `locate_element(target)`；
  - 命中则按 control（UIA `_click`）或 box（`_click_box_center`）点击，返回策略名；
  - 未命中且还有次数则 `time.sleep(retry_delay)`；
  - 全部耗尽抛 `ElementNotFoundError("未找到元素（重试 N 次后仍落空）：<trace 用 | 连接>")`。

### 2.2 sidecar `server.py`
- `/desktop/click_element` 接受可选 `retries`（整数 0–5，越界/缺失默认 2），透传给 picker；
- 协议 docstring 同步为 `body {"target", "retries"?: int}`。

### 2.3 引擎 / 客户端
- `SidecarClient.clickElement(target, retries?)`：body 带 `retries`（仅在是有限数时）。
- `DesktopLike.clickElement(target, retries?)`：接口加可选参数。
- `pickElement` 指令：新增参数 `retries`（「定位失败重试次数」，number，默认 2，钳制 0–5）；
  runner 把插值后的 retries 传给 `desktop.clickElement(target, retries)`，日志
  「按选择器定位并点击元素：X（重试上限 N 次）」。

### 2.4 测试
- `sidecar/tests/test_desktop_record.py`（+4 例，共 65）：用 `object.__new__(DesktopPicker)`
  绕过真实 UIA/钩子，注入假 locate：
  - 先失败后成功 → 重试 1 次后命中、只点一次；
  - 始终失败 → 重试满 2 次（共 3 次调用）抛错、消息含 trace；
  - `retries=0` → 只尝试一次；
  - coords 命中（control=None）→ 走坐标兜底点击。
- `sidecar/tests/test_desktop_pick.py`：三个 fake `click_element` 签名改为 `**_kw` 以兼容 retries。
- `src/engine/desktop/commands.test.ts`：pickElement 参数断言加 `retries`；spy 调用断言
  改为 `(ELEMENT, 2)`。

## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 重试放在哪一层 | sidecar `click_element` 内循环，不在引擎/主进程 | 重试与「重跑定位链」必须紧邻 UIA；引擎只透传次数 |
| 如何"重取窗口句柄" | 每次重试都重调 `locate_element`，其窗口回退已支持句柄失效→按标题重找 | 复用切片 2 既有回退逻辑，零新增状态 |
| 默认重试次数 | 2（共 3 次尝试），可配置 0–5 | 应对瞬态加载延迟；过久会拖慢失败流程 |
| 重试间隔 | 0.3s | 单测用 retry_delay=0 跑快；真实环境给应用一点加载时间 |
| 失败信息 | trace 拼进 ElementNotFoundError 消息 | 主进程 404 原样回运行日志，无需新增协议字段 |
| coords 兜底是否重试 | 不特殊处理 | coords 命中即点；若窗口移动导致点偏，靠"下次 run"或圈定录制/重拾取解决，不在本切片 |

## 5. 遗留与风险

1. **窗口句柄圈定录制范围仍未做**（需 UX 拍板：录制前如何指定目标窗口）——顺延切片 6。
2. **坐标兜底点偏未根治**：窗口移动后 coords 用旧 boundingBox 中心仍会点偏；重试不解决这个
   （coords 每次都"命中"）。根治要靠重拾取或实时窗口相对坐标。
3. **重试只解决瞬态**：元素真不存在时，3 次尝试+0.3s 约多花 0.6s 才报错，可接受。
4. **聚合阈值未校准**（350/800/400ms 常量）仍挂账。
5. **Tcl leaked 告警（既有）**：overlay 线程退出已知行为，功能无损。

## 6. 下一步建议（优先级排序）

1. **窗口句柄圈定录制范围 + 目标 PID 过滤**：录制开始前用现有 `/pick/start` 让用户点选目标窗口，
   取其顶层窗口 PID，录制钩子只保留该 PID 的事件（而非只排除自身）。需 UI 一步「选择录制窗口」。
2. **坐标兜底加固**：回放 coords 点击前按窗口标题重定位窗口，把旧 boundingBox 换算到窗口新偏移；
   或对纯坐标签名提示"建议重拾取"。
3. **聚合阈值校准**：录真实操作人工核对后调 CLICK_DEBOUNCE/TYPING_GAP/SCROLL_GAP，做成可配置。
4. **录制流程参数化**：把录制出的字面文本/坐标暴露为可改变量。
