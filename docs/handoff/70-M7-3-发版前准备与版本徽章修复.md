## 1. 本阶段目标与完成情况

按 69 号 §7 推荐转 B（发版前准备）。B 里真实 GitHub repo 需要用户建仓/授权，本切片只做不依赖凭证、且有实际价值的部分：

**A. 版本一致性核查：**
- package.json `version=0.1.0`；exe 文件版本资源 `FileVersion=0.1.0` / `ProductVersion=0.1.0.0`；asar 内 package.json=0.1.0；主进程 `app.getVersion()`=0.1.0。
- **发现真 bug**：装机版 TopBar 版本徽章显示 **v0.0.0**（应为 v0.1.0）。68 号当时以为"打包后 electron-builder 会注入正确版本，不影响"——假设错误。

**B. 根因与修复：**
- 主进程 `app.getVersion()` 正确返回 0.1.0（加 `APPVER=` 诊断确认）。
- 但 preload 里 `appVersion: electron.app.getVersion()` 在 **preload/渲染进程上下文**打包后返回 `"0.0.0"`（同样的 API 在主进程正常），contextBridge 把这个 0.0.0 暴露给 renderer，TopBar `?? '0.0.0'` 正好兜底成它。
- 修复：preload 改为 `require('../../package.json').version`（asar 根 package.json，相对 out/preload 上两级），并删掉随之未使用的 `app` import。typecheck 0。

**C. 重打安装包 + 静默装机 + 装机版 perf 复测：**
- `npm run dist` 重打，产物 `dist-installer/ruili-rpa-0.1.0-setup.exe` **230.9 MB**。
- `/S` 静默安装退出码 0；装到 `%LOCALAPPDATA%\Programs\ruili-rpa\锐流RPA.exe`。
- 装机版冷启动（win-unpacked，3 次）：

| 标记 | dev build（69 号） | 装机版（本切片） |
|---|---|---|
| main-eval | ~2.8 ms | ~3.0 ms |
| when-ready | ~241 ms | 255–262 ms |
| window-created | ~532 ms | 335–426 ms |
| did-finish-load | ~731 ms | 590–942 ms |
| ready-to-show（用户见窗） | ~827 ms | **593–1049 ms** |
| RSS @ ready-to-show | ~194 MB | 190–194 MB |
| heapUsed | ~49 MB | 32 MB |

**结论：装机版冷启动 ~0.6–1.0s，与 dev 同量级或更快；whenReady→window-created 段从 dev 的 ~290ms 缩到 ~80–160ms（asar 读 package/DB 比 dev fs 快）。heapUsed 装机版更低（32MB vs 49MB）。无性能阻塞。**

**D. SMOKE 验证：** 装机版 `RUILI_SMOKE=1` 截图正常（7 导航/首屏引导卡片/无白屏）；版本徽章不再常驻 v0.0.0（更新检查失败瞬时态 3s 后回 idle 显示 v0.1.0）。

## 5. 遗留问题与事故记录

1. **⚠️ package.json 中途被截断事故（本切片内）**：在一次 `npm run build` 前，package.json 从 3128 字节被截断成 502 字节，丢失 scripts/devDependencies/build 块，导致 npm 报 "Missing script build"。**未定位到根因**（前后只跑过 npx asar extract / npx electron 临时脚本，理论上不该碰项目 package.json；疑似某次 npx/electron-builder 进程副作用）。已从已知良好内容完整重建（含 build 配置），JSON 校验通过、build/dist 全跑通。**强烈建议下一步 `git add -A && git commit` 落一个基线**，否则再出这种损坏无法回滚。
2. **updater 404 是预期**：publish.owner/repo 仍是占位 `ruili-rpa/ruili-rpa`，装机版启动时检查更新会打一条 `HTTP_ERROR_404`（非致命，UI 3s 后自动恢复）。建真实 repo 后即消失。
3. `.rui` 双击/单实例的**真机资源管理器双击**仍未做（本切片只验证了启动与窗口，未模拟双击 .rui 文件）。
4. 诊断行 `APPVER=` 保留在 main（PERF 门控，零成本）。
