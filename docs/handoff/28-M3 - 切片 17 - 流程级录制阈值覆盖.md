## 1. 切片目标

关闭 NEXT-PROMPT 下一步建议 #1：**阈值面板细化**。在切片 12（全局 DB 阈值设置面板）基础上：

1. **按流程覆盖阈值**：FlowDoc 新增可选 `recordThresholds?: Partial<RecordThresholds>`；
   录制时 renderer 把当前流程的覆盖随 `record:start` 传给主进程，主进程既有 merge 链
   （DB 全局 base ← 调用方显式覆盖）自动生效，**主进程零改动**；
2. **录制中显示当前生效阈值**：点「录制」开启成功后，运行日志打印实际生效的四项阈值
   （全局值 + 流程覆盖叠加结果），有流程覆盖时括注覆盖了哪几项。

**不做**：录制过程中实时改阈值（本期只做"开启时打印 + 流程静态覆盖"，与切片 8/12 的
"录制开始前定阈值"模型一致）。

## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 覆盖粒度 | Partial，只存有值键；未存键跟随全局 | 与 sidecar `_apply_thresholds` 静默忽略未知键语义对齐；用户只改关心的项 |
| 优先级 | 流程覆盖 > 全局 DB > sidecar 常量 | 复用切片 12 既有 merge 顺序（base=DB，overrides=renderer 传值），主进程零改动 |
| 编辑入口 | 设置页签内「全局设置」与「本流程覆盖」上下两区 | 全局=所有流程默认；本流程=只写当前 flow；概念分层不混淆 |
| 生效时机 | 下一次点「录制」时生效（不热改进行中录制） | 与切片 8/12 模型一致；避免录制中途改聚合阈值产生歧义 |
| 生效阈值展示 | 录制开启成功后日志打印一行四项 + 覆盖括注 | 复用 push 日志通道，不加常驻 UI；失败静默不阻断录制 |
| 持久化 | flows.doc 整体 JSON 序列化 | 切片 2 起即为 blob 存盘，新字段无需建表/迁移 |

## 5. 遗留与风险

1. 流程覆盖未在「元素库/变量」侧展示；用户需打开「设置」页签才能看到当前流程是否有覆盖（开启录制时日志会提示）。
2. ThresholdPanel 的流程覆盖草稿未做撤销快照——「应用到本流程」走 commit() 已进撤销栈，但面板内输入过程不进撤销栈（与全局面板一致）。
3. 多标签页各流程独立覆盖；切换标签时面板草稿随 flow 同步（useEffect [flow]），未应用的草稿会被重置——预期行为。
4. 本切片为纯前端/主进程 IPC 透传，未做实机录制端到端冒烟（与切片 12 同口径，UI 手动验证项）。
