## 1. 切片目标

按切片 2 交接文档 §6 推荐优先级第 1 位，把「拾取/回放」扩为**智能录制 POC**：

1. **观察式事件流录制**：复用 `_HookThread`（record 模式，不吞输入），把用户在目标窗口的
   点击 / 输入 / 滚动按阈值聚合为指令序列：
   `click → pickElement`（与回退链共用 signature）、`input → typeText`、`scroll → scroll`；
2. **录制即入库**：指令里的元素签名走与拾取相同的 `saveElement` 去重 upsert（共用 dedupe key）；
3. **编辑器「录制」按钮与录制态展示**：录制中按钮变红「停止录制」、状态栏「● 录制中…」、
   与拾取/运行/单步/M1 互斥禁用；停止后指令追加为流程步骤；
4. **可选并行**：`/desktop/locate_element` dry-run（只定位不点击）→ 元素库「校验」按钮。

**不做的**（与切片 2 §1 一致）：不改 RunWireEvent 形状、不改既有 IPC 语义、不做录制后的
流程编辑/参数化（顺延）。

## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 录制是否吞输入 | 观察式透传（与拾取相反） | 用户在目标窗口的操作必须正常完成，录制只是旁观 |
| key 过滤时机 | **事件发生时**捕获前台 PID 随事件传递 | GUI 冒烟抓到真 bug：stop 聚合时用户已切回自身应用，聚合时查前台会把全部按键误过滤 |
| click/scroll 元素解析时机 | **事件发生时**在钩子线程解析签名 | stop 聚合时 UI 状态已变（开始菜单打开/关闭），聚合时解析会拿到错误/空元素 → 坐标兜底 |
| 钩子线程 UIA | 线程启动时 `CoInitializeEx` | `ControlFromPoint` 未初始化 COM 会抛 `OSError(22)`，事件时解析必然失败 |
| 叶控件不可用 | 向上找最近可用祖先（≤4 层） | 任务栏「开始」等叶控件常为空白子元素，父级才有 name（探针证实 leaf=ButtonControl 开始 48x40） |
| 元素入库 | 与拾取共用 `saveElement` + dedupe key | 同一元素重复录制不膨胀元素库；与拾取路径单一权威写入点一致 |
| 录制点击的坐标兜底 | 保留（windowHandle=0 空特征签名） | 与回退链最末级一致；元素库展示为「未命名元素」 |
| 指令 id | `r1, r2, …`（按生成序） | 简单可读；ts 保留事件时间便于排序 |
| typeText 参数 | 单参数 `text`（runner 插值） | 与现有指令插值机制一致，无需新运行时 |
| 校验端点 | dry-run 定位不点击，返回 strategy | 无副作用；供元素库「校验」与运行前预检（切片 2 §5.6 挂账项） |

### 4.4 调试过程沉淀（为何最终如此实现）
1. **key 过滤 bug**：`_aggregate` 在 stop 时查 `foreground_pid()`——用户操作目标窗口时前台是
   目标应用，stop 时已切回编辑器 → 全部按键被误过滤。修复：钩子回调在按键发生时记录前台 PID
   随事件传递（6 元组），聚合用事件时值；5 元组旧形状回退实时查询（单测兼容）。
2. **元素解析时机 bug**：click/scroll 的签名若在 stop 时解析，开始菜单等 UI 状态已变
   （`resolve (24,880)` 在 Stop 时解析到开始菜单面板）→ 坐标兜底。修复：钩子线程事件时解析。
3. **钩子线程 COM**：`ControlFromPoint` 报 `OSError(22, '尚未调用 CoInitialize。')` →
   `_HookThread.run()` 首行 `CoInitializeEx(None, 0)`（finally `CoUninitialize`）。
4. **GUI 自动化坐标（勿重试经验）**：
   - 冒烟进程必须 `SetProcessDpiAwareness(2)`，否则 GetWindowRect 与截图像素坐标系不一致；
   - 窗口位置会漂移（实测 (188,13,1200x800) ↔ (120,0,1360x860)）→ 每次点击前
     `click_client(hwnd, cx, cy)` 实时取 rect，禁止缓存坐标；
   - 导航页签/工具栏为**左锚定固定 client 坐标**（流程编辑器 (374,53)、录制 (313,127)，
     与窗口位置无关）；
   - 豆包主窗口（本会话宿主）可能覆盖锐流窗口左侧 → 点击前 `foreground(hwnd)` 置前；
   - 停止录制后须等 autosave（dirty 后 3s 定时）再查库（冒烟停 4.5s）。

## 5. 遗留与风险

1. **UIA 精确定位弱（既有）**：真实命中多靠 strict/coords；本轮冒烟中「开始」按钮在录制
   路径经祖先向上查找才拿到真实签名；其余系统区域（如任务栏空白处）仍会落坐标兜底。
2. **录制噪声**：全局钩子会录到非目标窗口的操作（如误点任务栏其它图标）；POC 只按
   app_pid（编辑器自身）过滤。后续可按窗口句柄/前台窗口过滤或人工删除步骤。
3. **输入聚合边界**：800ms 停顿分段对「慢速打字」会把一段话拆成多条 typeText；350ms 双击
   防抖对真实双击意图（如双击打开）会合并为一次点击——POC 阈值需真实样本校准。
4. **非文本键不产生指令**：Enter/Backspace/快捷键只截断输入段，不落盘——录制出的流程
   无法还原「按 Enter 提交」类操作（后续可加 key 指令种类）。
5. **Tcl leaked 告警（既有）**：overlay 线程退出时的已知行为，功能无损。
6. **SetWindowPos 右移不生效**：Electron 窗口显示时自管位置（冒烟里被还原）；GUI 冒烟靠
   client 相对坐标 + 实时 rect 已规避，不依赖窗口位置。
7. **Git 基线**：切片 1/2 基线已提交；本切片代码 + 交接文档待提交（见 §8）。
