## 1. 本阶段目标与完成情况

M5-5 文件监听触发器有两个遗留：①只监听单层目录，子目录新文件不触发；②大文件拷贝到一半时 `statSync` 立即返回，流程读到半截文件。本次修掉：

- **recursive 递归**（`src/main/filewatch.ts`）：`watch(path, { recursive: true })`；回调里把 `sub\nested.txt` 这种 Windows 反斜杠路径统一成 `/` 再过滤 `.` 开头的隐藏段。
- **等文件写完**：新增 `waitStable(full)` 轮询——每 200ms `statSync` 一次，连续两次 size 相同才认为落盘完成；最多等 5s，超时按当前 size 触发（避免永远挂着）。`onFile` 改 async。
- **顺手修一个防抖 bug**：原 `pending` Map 按 `taskId` 存，同一 task 下新事件覆盖旧 pending——子目录事件 `subdir` 会把同目录下 `nested.txt` 的 pending 冲掉，导致子目录文件不触发。改成按 `taskId|filename` 独立防抖（stop 仍清空全部）。

## 2. 产出物清单

- `src/main/filewatch.ts`：`STABLE_INTERVAL_MS=200` / `STABLE_TIMEOUT_MS=5000` 常量；`waitStable()`；watch 选项 `{recursive:true}` + 路径规范化；schedule/onFile 按 `taskId|filename` 独立防抖。
- `.runtime/smoke_filewatch_stable.mts`（gitignored）：临时目录 + fake ctx，验证①写一半再写完时 fire 时 size=完整 1100B 且 fire 在写完之后；②`subdir/nested.txt` 也触发。

## 5. 遗留问题

1. recursive 模式下 watch 整个目录树，文件量大的盘（如整个下载目录）会有性能开销；UI 选目录时建议提示用户选具体收件目录。
2. waitStable 对「边写边改」的文件（size 一直变）5s 后超时触发，可能仍读到不完整；但这种场景罕见。
3. 文件被移动/重命名不触发（只监听 rename/create 事件，未处理 move）。
