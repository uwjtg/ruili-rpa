## 1. 本阶段目标与完成情况

进 M5 第一块：计划书 §7 的「调度·机器人」起步——计划任务能建、能启停、到点自动跑。

1. **DB tasks 表**（`src/main/store/db.ts` migrate）：id/flow_id/name/trigger_type(cron|interval)/cron_expr/interval_ms/enabled/last_run_at/next_run_at/run_count/时间戳；CRUD：createTask/listTasks/listEnabledTasks/setTaskEnabled/deleteTask/markTaskRan；createTask 校验 flow 存在 + cron/interval 字段非空；
2. **调度器**（`src/main/scheduler.ts`，不依赖 Electron）：TaskScheduler 注入 loadFlow/fire/markRan 三回调；cron 型用 croner，interval 型用 setInterval（floor 1000ms 且 unref 不阻止退出）；reload 全量重建、stop 全停；非法 cron 表达式跳过不抛；loadFlow 返 null 跳过本次；
3. **主进程接线**（`src/main/index.ts`）：whenReady 开 DB 后 scheduler.reload(启用任务)；IPC `tasks:list/create/toggle/delete`，toggle/delete 后自动 reload；fire 回调直接 runManager.start(flow)；退出时 scheduler.stop()；
4. **preload + env.d.ts**：tasks.list/create/toggle/remove 桥接与窗口类型镜像；
5. **TriggersView 真实化**：任务卡片列表（名/触发描述/已跑次数/上次/下次）、新建表单（选流程/任务名/cron 或间隔分钟）、红色开关即时启停、删除。

## 5. 遗留问题

1. **错过补跑未做**：电脑关机/睡眠跳过的触发点不补跑（计划书「系统睡眠唤醒后对时补跑」留后续切片）；
2. **并发控制未做**：同一任务上一次还在跑时到点会再启一次 RunManager（单例 RunManager，第二次 start 会覆盖 interpreter，可能中断上一次）；后续加运行中互斥锁；
3. **执行记录/机器人视图未接**：TriggersView 只显示 run_count，没有每次运行的日志/状态详情（RobotsView 仍占位）；
4. **热键/文件监听触发器未做**（计划书 M4 的另外两类触发器）；
5. 调度触发运行时 renderer 看不到实时日志（runManager 事件仍推给主窗口，若用户没在编辑器页则日志流被丢弃）；
6. next_run_at 在任务创建时不算（只在第一次触发后写）；新建任务卡片下次显示「—」直到首次触发。
