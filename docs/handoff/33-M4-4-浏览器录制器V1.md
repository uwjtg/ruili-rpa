## 1. 本阶段目标与完成情况

M4-3 只做了"拾取单个元素"。本切片把它扩成**录制器**：在已开浏览器页面里正常操作，
点击/输入事件自动记录，停止后一键转成流程步骤。

1. `record-script.ts` 两段字符串：
   - `REC_START_FN`：注入 mousedown（capture，左键，记 cssPathOf）+ input（500ms 去抖，
     只录 text/textarea，记最终值）；事件 push 到 `window.__ruiliWebEvents`；
   - `REC_STOP_FN`：移除监听、清定时器、返回事件数组。
2. `WebSession.startWebRecord()/stopWebRecord()`：new Function 注入（同 pick-script 模式）。
3. 主进程 `web-record.ts` + IPC `web-record:start/stop` + preload `ruili.webRecord`。
4. 编辑器工具栏「● 录网页」按钮：开始→按钮变红「■ 停止网页录制」→停止→事件转
   `webClick(selector)` / `webInput(selector, value)` 追加到流程末尾。

**不做**：滚动录制（wheel → webScroll）；键盘按键（Enter/Tab）；导航/URL 变化录制；
iframe 内录制；等待/断言步骤。这些留 M4-5+。

## 5. 遗留问题

1. **真浏览器端到端未冒烟**：事件注入/去抖/选择器生成均未在真实浏览器跑过；
   linkedom 不支持 addEventListener/window，未写录制脚本单测。
2. 不录滚动、不录按键、不录导航——只能录"点哪、输什么"，翻页/下拉/切换 tab 抓不到。
3. input 去抖 500ms：用户输完立即停止会丢最后一次（定时器未触发）。
4. CSS 路径只取第一个 class token（同 pick-script 局限）。
5. 录制过程中页面导航（点了链接跳页）会让监听丢——新页面没注入脚本。
6. 未做"录制中可视化指示"（页面上无浮层提示正在录制）。

## 6. 对下一阶段的输入要求
