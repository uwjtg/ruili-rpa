### 1.1 冷启动基线（dev build `out/`，3 次取区间）

| 标记点 | 含义 | 3 次实测 |
|---|---|---|
| `main-eval` | 本 bundle 全部 import 求值完 | 2.7 – 2.8 ms |
| `when-ready` | `app.whenReady()` 回调开始 | 240.2 – 242.9 ms |
| `window-created` | `createWindow()` 返回（已开 DB / 重拉 LLM / initUpdater / 三个 reload） | 528.5 – 539.2 ms |
| `did-finish-load` | renderer HTML+JS 加载完成 | 727.1 – 735.9 ms |
| `ready-to-show` | 首屏可显示（用户看到窗） | 732.1 – 837.6 ms |

派生区间：
- `when-ready → window-created` ≈ **290 ms**（主进程同步段：openDb + reloadLlmClientFromDb + initUpdater + checkForUpdates + scheduler/hotkeys/fileWatcher reload）。
- `window-created → did-finish-load` ≈ **195–205 ms**（renderer 拉自己的 bundle）。
- `did-finish-load → ready-to-show` ≈ **0–100 ms**（React 首次绘制；1 次 0.7ms、2 次 ~100ms，方差大）。
- 从本 bundle 首行到**用户看到窗** ≈ **0.73 – 0.84 s**（不含 Electron runtime 自身在我们 bundle 之前的开销，那部分未内部计时）。

### 1.2 内存基线（ready-to-show 时点）

- RSS ≈ **193.9 – 194.5 MB**（Chromium + Node + Electron 壳的固有开销）
- `heapUsed` ≈ **48.5 – 48.9 MB**（V8 堆，很小，无内存问题信号）

### 1.3 包体基线

| 产物 | 原始 | gzip |
|---|---|---|
| `out/renderer/assets/index-*.js` | **947.7 kB**（报告口径 970.46 kB 含 hash 目录开销） | **179.8 kB** |
| `out/renderer/assets/index-*.css` | 15.2 kB | 4.2 kB |
| `out/main/index.js` | 133.4 kB | — |
| `out/preload/index.js` | 9.1 kB | — |

构成判断：
- 重依赖未进 renderer（grep 确认 exceljs/xlsx/playwright-core 仅 `src/engine/*`，主进程 `externalizeDepsPlugin` 已 externalize）。
- renderer 947.7 kB 主体 = React 19 + react-dom + react-router-dom + 7 视图全量 + 50 个内置模板（`shared/templates.ts` 41.6 KB 源）。
- **`App.tsx` 7 个视图全部静态 import，无 React.lazy 代码分割**（EditorView 单文件 51.4 KB 源）——这是 renderer 包体最大的可优化点。

## 5. 遗留问题

1. **本度量是 dev build（`out/`），非安装包内 asar 产物**。生产打包后启动会更快/更慢均有可能（asar 解包 vs 未打包 fs）；正式优化前应在 `dist-installer` 装机版上复测一遍同口径数字。
2. 未测「Electron runtime 启动 → 我们 bundle 首行」这段（约几百 ms），内部 `perfT0` 起算点偏晚。如需真实用户冷启动总时长，建议下一版从 PowerShell `Stopwatch` 包 `Start-Process` 测 wall-clock，并在 ready-to-show 后由主进程写一行 `PERF_WALL <ms>`。
3. `ready-to-show` 方差大（0.7ms / 827ms / 838ms），疑似首次渲染 JIT/字体加载；样本太少，不下结论。
4. 未做 CPU flame / 主进程事件循环 profile（需要 `--prof` 或 Chrome DevTools 协议，留到真要优化时再上）。
