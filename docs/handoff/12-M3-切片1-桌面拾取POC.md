# M3 切片 1：桌面元素拾取 POC（2026-09-24）

> 上游：《handoff/11-M2-切片4-AI面板与单步调试》《开发交接文档 V3》§5 编辑器交互清单（第 10 条元素拾取）、§7 开发边界、计划书 §5.1 选型
> 范围：M3 第一个可交付切片——桌面软件自动化第一步。Python UIA sidecar 拾取（pick:start/stop/result）+ pickElement 指令进 registry + 编辑器工具栏「拾取」按钮，拾取结果 append 为流程步骤。选择器回退链精化、智能录制、元素库持久化留后续切片。

## 1. 本切片目标与完成情况

**目标**：按计划书 §5.1 选型（Python UIA 子进程桥），主进程懒拉起 Python sidecar，暴露 `pick:start / pick:stop / pick:result`；实现"拾取模式"——全屏透明遮罩 + 鼠标移动高亮控件边框 + 点击回传 `{windowHandle, automationId, name, controlType, boundingBox}`；生成 `pickElement` 指令（进 cmd-schema + registry），拾取结果写参数；编辑器工具栏加「拾取」按钮，拾取到元素直接 append 一条 step 到当前流程。

**完成情况**：

- **sidecar 拾取器**（`sidecar/desktop_pick.py`）：`DesktopPicker` 类——全屏透明遮罩（tkinter overlay + `WS_EX_TRANSPARENT|WS_EX_LAYERED` 穿透 + 高亮矩形）+ 全局钩子（WH_MOUSE_LL / WH_KEYBOARD_LL）+ UIA 元素提取（`uiautomation`，ElementFromPoint）+ 点击回放（`click_element`，UIA 定位失败时 boundingBox 中心坐标兜底，即选择器回退链第 1 级）。辅助函数：`element_to_dict`（兼容 RECT 对象与 tuple）、`parse_target`、`enable_dpi_awareness`。
- **sidecar HTTP 端点**（`sidecar/server.py`）：`/pick/start`（阻塞等待点击/Esc/120s 超时）、`/pick/stop`、`/desktop/click_element`；模块级 `_PICKER` 单例（测试可替换）。
- **主进程控制器**（`src/main/pick.ts`）：`PickController`——懒拉起 sidecar（首次 start 时 spawn，失败结构化报错）、并发防重入、`pick:result` 事件推送（与 invoke 返回一致，供 UI 事件驱动复位）、`dispose()` 退出杀子进程。IPC `pick:start / pick:stop` 挂 `src/main/index.ts`，`window-all-closed` 里 dispose。
- **跨进程契约**（`src/shared/desktop-pick.ts`）：`PickedElement / PickReply / PickStopReply / ClickElementReply`；sidecar 客户端（`src/engine/sidecar/client.ts`）新增 `pickStart / pickStop / clickElement`（AbortController 超时）。
- **引擎指令**（`src/engine/desktop/commands.ts`）：`pickElement` 指令（桌面分组，params `[{key:'target'}]`，summary 展示元素摘要，runner 调 `clickElement` 回放）；`buildEngineRegistry` 注册（`src/engine/run/runManager.ts`）。
- **编辑器 UI**（`src/renderer/src/views/EditorView.tsx`）：工具栏「拾取」按钮（拾取中变「取消拾取」+ 底部日志提示）；拾取成功 append 一条 pickElement 步骤（`JSON.stringify(element)` 写入 `params.target`）；`pick:result` 事件兜底复位 picking 状态。

**关键调试结论（已解决，勿回退）**：

1. **穿透时序**：`WS_EX_TRANSPARENT|WS_EX_LAYERED` 必须在 `root.update()` 之后设置（窗口句柄先就绪）。先设后 update 会拾取到遮罩自身（TkChild 全屏）。代码顺序：`canvas.pack()` → `root.update()` → `SetWindowLongW` → `root.update()`。
2. **钩子线程**：全局 LL 钩子必须走 `_HookThread` 独立线程（自带 `GetMessageW` 消息泵，`PostThreadMessageW` 退出）。装在 tk mainloop 线程会在 Tcl 释放 GIL 期间触发 ctypes 回调导致崩溃（`PyEval_RestoreThread`）。`_HookThread` 回调不触碰 tkinter，事件经线程安全 `queue()` 由 tk 线程 `root.after(25, poll)` 轮询消费。
3. **坐标兜底**：UIA 深层子树匹配不到（如 doc_editor 空 name/automationId）→ 用拾取时 boundingBox 中心直接点击，已进 `click_element`（选择器回退链第 1 级）。窗口移动后坐标失效的风险记录在案，精确定位留给选择器回退链切片。
4. **ctypes.wintypes**：需显式 `import ctypes.wintypes`（`GetMessageW.argtypes` 引用）。
5. **Tcl 泄漏告警**：overlay 线程 `destroy()` 后清 `tkinter._default_root` 引用，进程退出时的 `RuntimeWarning: Tcl interpreter is leaked` 仍会出现一次——功能无损，列入遗留问题。

**未完成 / 留后续**：

- UIA 选择器回退链（property → ancestor → index → 坐标逐级回退）——M3 切片 2。
- 元素库持久化（拾取元素入库、复用）——M3 后续。
- 智能录制（点击/输入/滚动 → 指令序列）——M3 后续。
- 拾取精度对 Electron/Web 控件可辨识度低（渲染树在 UIA 中合并，name/automationId 常为空）——坐标兜底为主，真实 Win32 桌面应用效果更佳。

## 5. 遗留问题

1. **UIA 精确定位回放弱**：深层 UIA 子树匹配不到（doc_editor 空 name/automationId），当前回放以 boundingBox 坐标兜底为主。窗口移动/缩放后坐标失效——选择器回退链（property→ancestor→index→坐标）留 M3 切片 2。
2. **Tcl interpreter leaked 告警**：进程退出时出现一次 `RuntimeWarning`（gh-83274），功能无损；已清 `_default_root` 引用仍无法完全消除。
3. **Electron/Web 控件 UIA 可辨识度低**：拾取结果 name/automationId 常为空（渲染树合并），对 Electron 内控件以坐标语义为主；真实 Win32 应用可辨识度高。
4. **GUI 冒烟依赖 Win32 模拟点击**：computer_use_tool PIP 初始化失败不可用；冒烟脚本 `$env:TEMP/smoke_pick.py` 无固定仓库入口，建议后续把 GUI 冒烟脚本收进 `scripts/`。
5. **Git 基线仍缺**（2026-09 遗留，计划书 §9.1 挂账，沿用）。
6. **拾取模式未禁 Alt+Tab**：拾取中可切换窗口，遮罩 topmost 跟随，可接受（POC 阶段）。
