## 1. 本阶段目标与完成情况

handoff 37 §5 明确：抓取向导核心链路（识别→抓取→翻页）已在真站验证 6/7，但**录制器注入链路从未在真浏览器跑通**——旧 `smoke_web_live.mjs` 读 `.ts` 原文做正则替换时，`cssPathOf` 占位符是多行表达式 `${CSS_PATH_FN.replace(...)}`，内部含 `}`，正则 `\$\{[^}]+\}` 提前截断，替换失败、注入体残留字面 `${...}` 报语法错误（生产 TS 编译期已内联，非产品 bug）。

本切片不写新产品代码，只把这块未验证链路关掉，并顺手把旧脚本修绿：

1. **新增 `.runtime/smoke_recorder_live.mts`**：用 `vite-node` 直接 `import` 编译后的 `RealWebSession`（其内部注入的 `CSS_PATH_FN + REC_START_FN` 已是 TS 模块加载期内联好的字符串，与生产一致），点击/输入/滚动/按键全部走 `RealWebSession` 自己的方法——即 `webClick/webInput/webScroll/webPressKey` 指令背后同一层调用，是对"录制器注入 + 事件采集 + 导航重注入"最忠实的端到端冒烟。
2. **修 `.runtime/smoke_web_live.mjs` 录制器段**：把读 `.ts` 原文的替换改为锚定包装块首尾的跨行懒匹配 + 复刻 record-script 的 `.replace()` 剥出函数体，旧脚本从 6/7 提到 7/7。

**真站（quotes.toscrape.com，系统 Chrome channel:'chrome'，无头）结果**：

新脚本 `npx vite-node .runtime/smoke_recorder_live.mts` **10/10 PASS**：
- 打开 /login；录制浮层 badge 注入；
- click 捕到 `#username`；
- fill 两条值正确（`demo-user` / `secret-pass`，500ms 去抖落盘）；
- scroll deltaY=500（300ms 去抖落盘）；
- 功能键 `Tab`/`Enter`；
- **修饰键 `Control+C`**（M4-9 首次真浏览器验证）；
- 停止后 badge 移除；
- **跨导航自动重注入**（M4-5 首次真浏览器验证）：goto 首页后 `__ruiliWebRecording` 重新置位，点击 `.quote:nth-of-type(1)` 仍捕到 click。

旧脚本 `node .runtime/smoke_web_live.mjs` **7/7 PASS**（含录制器 click 事件）。

## 5. 遗留问题

1. **有头浏览器人工冒烟仍未做**：本脚本无头（headless:true）、自动驱动，已覆盖事件采集正确性；但"开有头 Chrome→人眼看到红色 badge→手动点选→步骤进流程编辑器"这条 UI 闭环仍需用户手动验一次（编辑器「录网页」按钮 → IPC web-record:start → 停止 → 步骤追加）。
2. 录制事件→流程步骤的转换（渲染层把 click/fill/scroll/key 转成 webClick/webInput/webScroll/webPressKey step）仍只靠单元测试，未在真实录完后人工核对步骤参数。
3. 导航后事件连续性：`framenavigated` 重注入会在新文档重置 `__ruiliWebEvents=[]`，跨页导航前已采集的事件留在旧文档、stop 时取不到（设计如此，单文档采集正确；若以后要跨页合并事件需另设计）。
4. iframe 支持仍未做。
