# 阶段 4 交接文档（贯通与 AI：日志流 IPC + LLM 配置化 + function-calling）

> 日期：2026-09-24 · 上游：《接力开发模式说明》《计划书 V1.1》《开发交接文档 V3》《handoff/03》
> 范围：T7（日志流 IPC）+ T8（LLM 配置化 + function-calling）

## 1. 本阶段目标与完成情况

**目标**：把阶段 2/3 的引擎与主进程、渲染端打通——运行事件经 IPC 流式推到日志面板；LLM Provider 配置化可切换；function-calling 能生成合法且可真实跑通的流程 AST。

**完成情况**：三项验收（§2）均达成。

- **日志流 IPC**：新增 `RunManager`（框架无关、可单测）聚合全部指令组（demo/web/excel/sidecar），把进程内 `RunEvents` 序列化成纯 JSON 的 `RunWireEvent`，经主进程 `run:event` 推给渲染端；preload 暴露 `run.start/startDemo/resume/stop/onEvent`。
- **EditorView 真实化（最小贯通版）**：运行/停止/继续按钮 + 流式日志面板，订阅 `run:event` 实时渲染带时间戳、四级配色的日志；不再是占位。
- **LLM 配置化（决策⑤）**：`LlmClient` 走 OpenAI 兼容 `/chat/completions`（全局 fetch，无 SDK），多 Provider 配置 `{name,baseURL,apiKey,model}`，`setActive` 切换；apiKey 留在主进程，渲染端只发 prompt。内置 cloud/local 双 Provider，baseURL/key/model 全部走环境变量覆盖（`RUILI_LLM_*`）。
- **function-calling → AST**：`generateFlow()` 把指令目录压成一个 `build_flow` 工具（cmdId 用 enum），模型一次返回结构化 steps，映射成 `FlowDoc`；并闭合阶段 2 遗留——新增 `validateFlow()` 在运行前校验未注册指令/空块。
- **本地 POC 无外网/无 key**：`poc:llm` 起本地 mock OpenAI 服务，验证 A/B 切换凭据正确、B 生成的 3 步流程被 Interpreter 真跑通。

**未完成 / 留后续**：
- 完整拖拽流程编辑器（指令库/参数面板/变量/撤销重做/多标签）仍是 M2 范围；本阶段 EditorView 只做「运行 + 日志」贯通。
- LLM 设置界面（输入 baseURL/key/model、Provider 下拉）未做——目前靠环境变量；设置界面进 M2。
- function-calling 暂只支持扁平叶子步骤，不生成嵌套块（loop/if children）；模型多步编排留后续。
- 真实 LLM（智谱/DeepSeek/OpenAI）未接真实 key 实测，仅以本地 mock 验证链路。

## 5. 遗留问题（含影响与建议）

1. **日志面板未在真实 GUI 里人工冒烟**：事件链路经单测 + build 验证，但未在打开的 Electron 窗口里肉眼看日志流动。建议阶段 6 出口演示时一并验证（`npm run dev` → 编辑器 → 运行演示流程）。
2. **LLM 设置 UI 未做**：Provider 切换目前靠环境变量 + `llm:set-provider` IPC，无界面。M2 编辑器/设置里补。
3. **function-calling 不生成嵌套块**：当前只产扁平叶子步骤；loop/if 的 children 生成留待模型多轮/工具描述增强。
4. **真实 LLM 未连实测**：mock 只证明协议与解析链路；接真实智谱/DeepSeek 需用户提供 key（环境变量），阶段 5/M5 指令扩充时验。
5. **一次只跑一个流程**：RunManager 单例，并发运行未做（机器人模式 M4 才需要队列）。
6. **Git 基线仍缺**（沿用前三阶段）。
