## 5. 遗留问题

1. **真浏览器端到端未冒烟**：页面脚本经 linkedom 单测验证逻辑正确，但未在真实
   Chrome/Edge 上跑过完整向导（识别→字段→CSV）。下一切片首要是手动冒烟一个真实列表站。
2. **示例选择器靠手填**：未做 CDP 浏览器内点选拾取（备选大项）；业务用户需从
   开发者工具复制选择器，体验弱于影刀。
3. **聚类启发式**：只按 tag+className 分组取最大兄弟组；对 class 带随机后缀
   （Vue/React 构建产物如 `product_abc123`）的站点会失效，需后续加"忽略 hash 后缀"
   与祖先路径兜底。
4. **导出仅 CSV**：未接 exceljs 写 .xlsx（V1 够用，用户可 Excel 打开 CSV）。
5. **翻页/入抓未做**：单页列表。
6. lint 基线告警（EditorView setState-in-effect、FlowSummary 未用）非本切片引入，未动。

## 6. 对下一阶段的输入要求

- WebSession 已加 `eval(fnBody, arg)`；后续浏览器录制器/CDP 拾取器可复用同一注入通道，
  不要再造第二个浏览器桥。
- 页面脚本模式定下来：**自函数字符串 + `new Function` 包装 + linkedom 单测**，
  新增页面内能力照此模式（生产/测试同一份逻辑）。
- `webScrapeList` 的 fieldsJson 是 JSON 字符串参数（与 pickElement target 插值 JSON
  同模式）；运行时已 interpolate listSelector/csvPath。
- 下一步建议（按优先级）：
  1. **真站冒烟 + 10 站基准**：在 2-3 个真实列表站跑通向导，记录成功率，补
     class-hash 去抖与祖先路径兜底；
  2. **浏览器录制器（CDP）**：页面内点击拾取 + 高亮（备选大项，可复用 eval 注入通道）；
  3. 翻页抓取 / XLSX 导出 / 详情页入抓。
