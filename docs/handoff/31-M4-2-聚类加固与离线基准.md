## 1. 本阶段目标与完成情况

M4-1 交付了抓取向导闭环，但聚类算法是最朴素的"tag+完整 class 分组"，对真实站点
三种常见形态会失效：
- **class 带构建 hash 后缀**（`product_abc123` / emotion 的 `css-1a2b3cd`）——每个实例
  class 不同，聚不到一组；
- **纯 tag 无 class 兄弟**（`<div class="list"><div>…`）——`div` 选择器全文命中过宽；
- **table 表格**——`<tr>` 同理过宽。

本切片：
1. 聚类分组前 `normClass` 剥离尾部 hash（`[-_][a-zA-Z0-9]{6,}$`），让同组件不同实例聚到一起；
2. 生成 listSelector 三分支：
   - 常规：`tag.normClass`；
   - hash 类：`tag[class*="stem"]`（把不同 hash 实例都选中）；
   - 纯 tag 组：`父选择器 > tag`（父有 class 用 `.cls`，无则用父 tag 如 `tbody > tr`）；
3. `relPath` 字段选择器在同父同 tag 多于 1 时加 `:nth-of-type(n)` 消歧；
4. 新增 `benchmark.test.ts`：10 种典型列表 HTML 形态离线基准，每个 fixture 断言
   识别成功 + itemCount 正确 + 首行字段值正确；末尾断言通过率 ≥8/10。

**不做**：真站浏览器冒烟（需用户在真实 Chrome/Edge 打开电商/搜索/后台站，留手动）；
浏览器内点选拾取（CDP 大项）；翻页/详情入抓。

**算法要点**：
- `normClass(raw)`：split 后每个 token 剥 `[-_][a-zA-Z0-9]{6,}$`，保留前 3 个 join；
- `hasHashTok` 判据：示例元素任一 token 命中尾部 hash → 走 `[class*=stem]` 分支；
- 纯 tag 分支用 `sample.parentElement` 的 class/tag 拼 `父 > tag`，避免 `div` 全文命中。

## 5. 遗留问题

1. **真站未冒烟**：离线 fixture 覆盖了典型形态，但真实站（CDN/懒加载/iframe/异步渲染）
   仍可能有意外；下一切片建议用户手动开一个真实列表站跑向导。
2. `[class*="stem"]` 可能误伤（别的元素 class 含同 stem 字符串）；V1 接受，
   后续可加"容器限定"（祖先路径前缀）。
3. 多 class 顺序不同（`item card` vs `card item`）仍分两组——已知局限，未处理。
4. iframe 内列表不识别（示例选择器跨 iframe 不适用）。
5. 候选字段 relPath 的 `:nth-of-type` 基于示例项，其他项同位置结构应一致——假设同构，
   异构列表（每项字段数不同）会取空。
